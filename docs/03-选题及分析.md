## 二、选题背景与问题定义

学生的记录行为高度碎片化：课程笔记在备忘录、待办在便签 App、生活费在记账 App、复习导图在 XMind——**信息分散在 4~5 个工具中，互不相通，"存了等于丢了"**。

市场侧数据支撑：2025 年中国跨平台笔记应用市场营收约 142.2 亿元（同比 +18.5%），Z 世代与新锐白领合计占用户 63.4%，学生是主力人群（博研咨询）。对现有产品的调研（印象笔记、Notion、腾讯 ima、Obsidian、语雀、滴答清单、鲨鱼记账等 7 款）表明：面向团队协作的产品过重，单点工具（纯待办/纯记账）无法沉淀知识，**缺少"学生向、轻量、多功能互通"的产品**。

**问题定义**：设计并实现一个 Web 端个人知识管理系统，在一个平台内打通"笔记 + 待办 + 思维导图 + 轻记账 + AI 助手"，使一处记录可多形态复用（笔记→导图、笔记→待办、笔记→AI 语料）。

## 三、目标与范围（遵循"选题要小而不是大"）

- 必做（验收红线）：用户系统、Quill 富文本笔记（兼容旧 Markdown，分组/标签/搜索）、待办、思维导图、AI 摘要与自动标签
- 应做：轻记账与月度统计
- 本轮延期：社区分享、独立数据看板、AI 问答
- 明确不做：多端同步、协作编辑、OCR/语音、移动端

## 四、可行性分析

| 维度 | 分析 | 结论 |
|------|------|------|
| 技术 | 后端 Flask + SQLite，前端 Vue 3（Vite 构建）+ Bootstrap5；导图/图表/编辑器使用 jsMind/ECharts/Quill，旧 Markdown 使用 marked.js 兼容；组员主力语言 Python，前端按组件拆分推进，边写边对照官方文档 | 可行 |
| 风险 | AI 依赖外网 API → 设计"真实 API + 本地规则引擎自动降级"适配器，断网可演示 | 已化解 |
| 进度 | 实验课隔周上、线下并行开发；按 Sprint 0~7 拆解（见开发任务书），红线模块在"实现/测试/验收"环节前完成 | 可行 |
| 工具 | git 版本控制（课程硬性要求）；编码阶段使用 AI 工具辅助（课程鼓励项） | 满足 |

## 五、预期创新点

1. **AI 服务降级架构**：API 与本地引擎同一接口，演示现场断网自动切换并展示引擎标识，保证健壮性。
2. **笔记多形态复用**：一条笔记可生成导图、关联待办、作为 AI 语料，体现模块间数据互通的设计价值。
